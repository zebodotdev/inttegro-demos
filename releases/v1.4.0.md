# Inttegro demos 1.4.0

This release adds a portable Docker workflow to the server demo suite without
changing the checkout integration contract.

## Changes

- Adds production multi-stage Dockerfiles for Next.js and Nuxt. The Next.js
  image runs standalone output; the Nuxt image runs the generated Nitro server.
- Adds one-command Docker Compose workflows to every currently runnable server
  demo. `docker compose up --build --wait` builds the image, starts it in the
  background, and waits for the service to be running or healthy.
- Adds the official Docker Ocean Blue mark and a **Run with Docker** action to
  demo READMEs, the public catalogue, and Studio deployment options.
- Makes the Next.js Docker workflow available as the companion backend path for
  SwiftUI, Android Compose, Flutter, and React Native demos.
- Keeps Rails secure by default in hosted production while allowing its direct
  localhost Compose path to disable the HTTPS redirect explicitly.
- Advances suite, per-demo, and deployment references to version 1.4.0. Older
  releases remain unchanged for existing Studio permalinks.

## Boundaries

Docker is a local or self-hosted container path, not an infrastructure account.
It does not provision DNS, TLS, secret storage, or a public cloud service. The
Cloudflare, Cloud Run, Railway, Render, and Vercel actions remain separate
provider-specific deployment flows.

Spring Boot retains its Dockerfile but does not advertise the Compose action
until Inttegro Java SDK 5.0.0 is publicly resolvable. AWS App Runner remains
unavailable as a universal public target because new-customer access and source
connections are account-specific, and this release does not publish ECR images.

## Verification

The repository-wide contract check validates release metadata, Docker and
Compose coverage, provider ordering, immutable deployment references, required
environment values, catalogue metadata, source documentation, and SDK naming.
Next.js type checking, five focused tests, and its production standalone build
passed. Nuxt type checking, three focused tests, its production build, and a
live Nitro `/health` check passed. Compose YAML and Rails' secure-default
configuration also passed focused checks.

The local machine did not provide a running Docker daemon or Compose plugin, so
the container images themselves were not executed before release. Docker
actions are therefore marked prepared rather than verified.

## Release safety

Compose loads the reader's local environment file only at container runtime.
No Inttegro credentials are stored in an image, Compose contract, deployment
URL, source file, or release artifact.
