# Inttegro demos 1.8.0

Release 1.8.0 adds a production-shaped Astro integration to the public demo
suite, pairs FastAPI with Angular and NestJS with Svelte, and extends the
Openfield fundraiser story across three distinct server runtime models.

## Framework pairings

- FastAPI serves an Angular 21 checkout island that uses the published
  `@inttegro/angular` adapter for embedded Checkout and places the same official
  component inside an application-owned dialog for the modal presentation.
- NestJS serves an equivalent Svelte 5 island built with
  `@inttegro/svelte`, keeping campaign rendering and trusted Order creation in
  Nest while Svelte owns the interactive payment presentation.
- Both demos retain the hosted-page `303` path as a progressively enhanced
  fallback and expose only the finalized Order ID to browser code.

## Astro integration

- Astro components render the responsive Openfield campaign and result states.
- A framework-native server endpoint validates supporters, resolves the trusted
  GHS 50 catalogue Price, and creates a finalized Order with the Inttegro
  TypeScript SDK.
- Embedded, modal, and hosted-page Checkout share one server-authoritative
  Order contract and expose only the finalized Order ID to browser integrations.
- The standalone Node adapter provides a portable server runtime with Docker,
  Render, Railway, and Cloud Run configuration.
- Same-origin form protection, a bounded request body, stable idempotency, safe
  errors, and explicit completion and cancellation URLs are enabled by default.

## Release guarantees

The suite tag and all 16 per-demo tags resolve to one immutable signed commit.
Reader-owned deployment links target release-specific branches, and Studio
links documentation and source examples to the same version.

The first-party Astro deployment is published at
`https://astro-demo.inttegro.dev`. Spring Boot remains published as source but
unavailable for live or remote builds until the Inttegro Java SDK dependency is
public.
